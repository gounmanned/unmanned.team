Google Workspace

This guide covers connecting a client's Google Workspace to Vex so it can pull data from:

  • Google Workspace Alert Center
  • Google Admin Directory Users

The setup has two parts. Part 1 is done once, ever, by us — it creates a single service account and Client ID that every client delegates to. Part 2 is done once per client, by their Super Admin — it's a short delegation step in their own Admin Console. Once Part 1 exists, onboarding a new client is just Part 2.

Never send a client the JSON key. Only the Client ID and the scope list below get shared with customers. The JSON key stays in Vex and in our secrets manager.

MSP duty — do once
Part 1: Create the Service Account & Client ID

This happens one time in our own GCP project. It is not repeated per client.

1. Create a Google Cloud project

  1. Go to Google Cloud Console.
  2. Create a new project (e.g. pink-duck-monitor), or choose the existing one we use for this.

2. Enable the required APIs

  1. In the project, go to APIs & Services → Library.
  2. Enable the Admin SDK API.
  3. Also enable the Google Workspace Alert Center API.

3. Create the service account

  1. Go to IAM & Admin → Service Accounts → Create Service Account.
  2. Set a name like security-monitor and click "Create and Continue".
  3. Click Done. No project-level IAM roles are needed.

4. Allow key creation (only if blocked)

Some orgs enforce a policy that blocks downloadable service account keys. If key creation fails:

  1. From the console, go "back" one directory to the organization.
  2. Go to Organization Policies.
  3. Search for iam.disableServiceAccountKeyCreation.
  4. Click Manage Policy, change from enforced to not enforced, and Save.

5. Generate the JSON key

  1. Open the service account, go to the Keys tab.
  2. Click "Add Key" → "Create new key".
  3. Select JSON, click Create.
  4. Save the downloaded .json file directly into our secrets manager. This one file authenticates against every client we onboard, so it never lives in a shared drive, repo, or local Downloads folder.

6. Enable domain-wide delegation and copy the Client ID

  1. Still in the service account, click "Show Domain-wide Delegation" and enable it.
  2. Copy the numeric Client ID shown. This is the ID every client will paste into their own Admin Console in Part 2.

7. Load the key into Vex

  1. Go to Vex and paste the JSON key contents into the monitor, then Save.

Customer duty — repeat per client
Part 2: Grant Delegation (Client's Super Admin)

Send the client's Super Admin (admin@their-domain.com) the Client ID from Step 6 above, plus the scope list below, and have them do the following in their own Workspace:

  1. Visit Admin Console → Security → API Controls.
  2. Click "Manage Domain-Wide Delegation".
  3. Click "Add new".
  4. Paste our Client ID.
  5. Add the following scopes:
    https://www.googleapis.com/auth/apps.alerts
    https://www.googleapis.com/auth/drive.readonly
    https://www.googleapis.com/auth/admin.directory.user.readonly
    https://www.googleapis.com/auth/admin.directory.device.chromeos.readonly
  1. Click Save.

That's the entire client-side lift. They never create a GCP project, service account, or key — they're only ever authorizing our existing Client ID to access their domain.
