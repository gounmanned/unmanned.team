Okta API Token for System Log

This guide walks you through creating an Okta API token with read-only access to the System Log, and storing it so VEX can periodically retrieve audit events from your Okta org.

Prerequisites

  • You have Super Admin or Security Admin access to your Okta organization.
  • You know your Okta org's base URL (e.g., https://company.okta.com or https://company.oktapreview.com).

Step 1: Access API Token Settings

  1. Log into the Okta Admin Console with an admin account.
  2. In the left navigation, go to Security → API.
  3. Click the Tokens tab.
  4. Click Create Token.

Step 2: Configure the Token

  1. Set the Token name to VEX System Log Reader.
  2. Click Create Token.

Okta API tokens inherit the permissions of the admin who creates them. To grant read-only access to the System Log, the token must be created by an admin with a role that includes logs:read permission (e.g., Super Admin, Security Admin, or a custom role with the Read System Log privilege). The token itself has no independent scope configuration — its capabilities mirror the creator's role.

Step 3: Verify Permissions

  1. After creation, note the admin role used to create the token.
  2. Confirm that role includes the Read System Log privilege:
Admin Console → Security → Administrators → [Role] → Privileges
└── Logs → Read System Log ✓

If the creating admin lacks Read System Log, the token will return 403 Forbidden when VEX calls /api/v1/logs. Create the token using an account with sufficient privileges, or assign the privilege to a custom role and have that role's admin create the token.

Step 4: Copy Your Token

  1. Copy the generated token immediately — Okta will not show it again after you leave the page.
  2. Store it securely before proceeding.

Step 5: Save

Inside VEX, add your credential in the following JSON format, including your Okta org's base URL:

{
  "api_token": "$OKTA_TOKEN",
  "base_url": "https://company.okta.com"
}

base_url is your Okta organization's base URL. Do not include a trailing slash. Examples:

  • https://company.okta.com (production)
  • https://company.oktapreview.com (preview/sandbox)
  • https://company-admin.okta.com (custom domain)

Once registered, VEX will use this token to call GET /api/v1/logs and retrieve System Log events for analysis.

Token Rotation & Expiration

  • Okta API tokens do not expire automatically unless your org has a token expiration policy configured (Security → API → Token Settings).
  • Best practice: rotate tokens every 90–180 days. Create a new token, update VEX, then revoke the old one.
  • To revoke: Admin Console → Security → API → Tokens → click the token's Revoke button.
