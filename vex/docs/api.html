Authentication

Authenticate with the API

Vex uses AWS Cognito, fronted by a hosted login page. Send users to the hosted UI, exchange the returned code for an ID token, then pass it as a Bearer value in the Authorization header on every request.

authenticate.js JavaScript 
const HOSTED_UI    = 'https://lock-unmanned.auth.us-east-2.amazoncognito.com';
const CLIENT_ID    = '2314edi18c3o3t8sroh2u2hucf';
const REDIRECT_URI = 'https://yourapp.example.com/callback';

// 1. Send the user to the hosted login page
function login() {
  const params = new URLSearchParams({
    client_id: CLIENT_ID,
    response_type: 'code',
    scope: 'email openid profile',
    redirect_uri: REDIRECT_URI,
  });
  window.location.href = `${HOSTED_UI}/login?${params}`;
}

// 2. Exchange the ?code= param on your callback for tokens
async function exchange(code) {
  const body = new URLSearchParams({
    grant_type: 'authorization_code',
    client_id: CLIENT_ID,
    redirect_uri: REDIRECT_URI,
    code,
  });

  const resp = await fetch(`${HOSTED_UI}/oauth2/token`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body,
  });

  const { id_token } = await resp.json();
  return id_token;
}

const idToken = await exchange(code);

// Attach to every request
const headers = {
  'Authorization': `Bearer ${idToken}`,
  'Content-Type': 'application/json',
};
ID tokens are short-lived. A request that comes back 401 means yours has expired — send the user through the hosted login page again rather than trying to refresh in place.
Signals

List signals

Returns signals in your account. Filter by status or date. For MSP-wide queries across every managed account, use /managed/signal instead.

GET
/signal?status=OA
Returns signals, filterable by status code or month.
GET
/managed/signal
MSP-wide: returns signals across every managed account.
CodeLabelDescription
OAActiveOpen and unresolved. Default signal queue view.
OBBlockedWaiting on someone before work can continue.
CHClosedResolved and closed by a human.
CVClosed by VexVex closed it directly with high confidence.
CRAccepted riskThe account accepted the risk on this signal.
CDDuplicateSuperseded by another signal covering the same issue.
CFFalse positiveNothing actionable to complete.
Any status starting with O counts as open, and anything starting with C counts as closed — PATCH enforces that a new status matches one of those two prefixes.
list-signals.js JavaScript 

// Active signals in current account
const active = await fetch(`${BASE}/signal?status=OA`, { headers })
  .then(r => r.json());

// Signals updated in a given month
const month = await fetch(`${BASE}/signal?date=2026-01`, { headers })
  .then(r => r.json());

// MSP-wide: active across every managed account
const managedActive = await fetch(`${BASE}/managed/signal`, { headers })
  .then(r => r.json());
Signals

Get a signal's thread

Fetch the ordered thread of updates posted to a signal. This does not return the signal's own fields (status, severity, asset) — pull those from the list endpoint above.

GET
/signal/{id}
Returns the thread of updates posted to a signal, oldest first.
get-signal.js JavaScript 
const thread = await fetch(`${BASE}/signal/482913`, { headers })
  .then(r => r.json());
Signals

Create a signal

One step: POST /signal with a source, severity, and the raw value of what happened. Vex writes the headline itself. Signals carry a severity from 1 (critical) to 5 (info).

To add a follow-up to an existing signal — a threaded message, like the next entry in a conversation — POST /signal/{id} instead.

POST
/signal
Creates a new signal. Returns the object including its ID.
POST
/signal/{id}
Adds a follow-up update to an existing signal's thread.
create-signal.js JavaScript 
// Step 1: Create the signal — Vex generates the headline
const signal = await fetch(`${BASE}/signal`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    source:   'api',       // 'google' | 'microsoft' | 'cloudflare' | 'level' | 'api'
    severity: 2,            // 1=critical 2=high 3=medium 4=low 5=info
    asset:    'east-wing-printer-03',
    value:    'HP LaserJet not responding. Tried power cycling — no change.',
  }),
}).then(r => r.json());

// Step 2: Add a follow-up to the thread
await fetch(`${BASE}/signal/${signal.id}`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    value: 'Replaced the fuser unit — printer back online.',
  }),
}).then(r => r.json());
Signals

Update or delete a signal

Patch status, severity, asset, or source — only the fields you include are changed. Deleting is permanent: it removes the signal, its full thread, and any generated file.

PATCH
/signal/{id}
Partial update. Send only the fields to change.
DEL
/signal/{id}
Permanently deletes the signal and its thread.
update-signal.js JavaScript 
// Close a signal
await fetch(`${BASE}/signal/482913`, {
  method: 'PATCH',
  headers,
  body: JSON.stringify({ status: 'CH' }),
}).then(r => r.json());

// Re-triage severity
await fetch(`${BASE}/signal/482913`, {
  method: 'PATCH',
  headers,
  body: JSON.stringify({ severity: 1 }),
}).then(r => r.json());

// Delete permanently
await fetch(`${BASE}/signal/482913`, {
  method: 'DELETE', headers,
});
Monitors

List monitors

Monitors are integrations Vex connects to on your behalf. Once connected, Vex continuously scans for the signals that feed its breach-scenario engine.

microsoft
M365 — users, mailboxes, MFA, conditional access, SharePoint
google
Workspace — users, Drive, Gmail security, 2-step verification
cloudflare
DNS records, audit logs, zone security posture
level
RMM — endpoint patch status, device health
GET
/monitor
Returns the keys of every monitor connected on the current account.
list-monitors.js JavaScript 
const monitors = await fetch(`${BASE}/monitor`, { headers })
  .then(r => r.json());
Monitors

Connect a monitor

Connect a new monitor by POSTing credentials to /monitor/{name}. The body is stored as-is — its shape is whatever that integration's connector expects, so use the credential formats below for the built-in integrations.

POST
/monitor/{name}
Connects a monitor. Body is the credentials object for that integration.
connect-monitor.js JavaScript 
// Google Workspace — service account JSON key
await fetch(`${BASE}/monitor/google`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    type: 'service_account',
    project_id: 'your-project-id',
    private_key_id: '...',
    private_key: '-----BEGIN RSA PRIVATE KEY-----\n...',
    client_email: 'vex@your-project.iam.gserviceaccount.com',
  }),
}).then(r => r.json());

// Microsoft 365 — app registration credentials
await fetch(`${BASE}/monitor/microsoft`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    tenant_id:     'your-tenant-id',
    client_id:     'your-app-client-id',
    client_secret: 'your-app-secret',
  }),
}).then(r => r.json());
Monitors

Disconnect a monitor

Send DELETE to /monitor/{key}. Vex removes the stored credential and stops scanning immediately. Signals the monitor already produced are left in place.

DEL
/monitor/{key}
Disconnects the monitor and removes its stored credential.
disconnect-monitor.js JavaScript 
await fetch(`${BASE}/monitor/google`, {
  method: 'DELETE',
  headers,
});
Multi-tenancy

Account delegation

By default every API call operates in your own account. To act on behalf of a managed customer, pass the account header set to their domain. Vex scopes all reads and writes to that account for any request carrying the header.

The header only works once a grant exists between you and that account — created the first time they accept your invitation (see below). No separate login or token exchange, just the header.

The account header works on every endpoint — signals, monitors, files, and audit. Drop it to fall back to your own account.
GET
/managed/grants
Returns every account currently granted to you.
GET
/managed/overview?account={domain}
Returns the account summary for one managed customer.
delegation.js JavaScript 
// Act on behalf of a managed account
const clientHeaders = { ...headers, 'account': 'acmecorp.com' };

// Active signals in the managed account
const signals = await fetch(`${BASE}/signal?status=OA`, { headers: clientHeaders })
  .then(r => r.json());

// Loop every account you manage, print active signal counts
const accounts = await fetch(`${BASE}/managed/grants`, { headers })
  .then(r => r.json());

for (const domain of Object.keys(accounts)) {
  const active = await fetch(`${BASE}/signal?status=OA`, {
    headers: { ...headers, account: domain },
  }).then(r => r.json());
  console.log(domain, active.length, 'active');
}
Multi-tenancy

Invite a customer

Invite a customer to be managed by you. They receive an email to accept, which creates the grant that account-header delegation relies on above.

POST
/managed/invite
Sends an invitation email. Accepting it creates the grant automatically.
GET
/managed/grants?for=pending
Lists invitations sent but not yet accepted.
POST
/managed/grants/{account}/{user}
Grants a teammate access to an account you already manage.
DEL
/managed/grants/{account}/{user}
Revokes a teammate's access to that account.
invite-customer.js JavaScript 
// Send invitation
await fetch(`${BASE}/managed/invite`, {
  method: 'POST',
  headers,
  body: JSON.stringify({ to: 'customer@acmecorp.com' }),
});

// See invitations still awaiting acceptance
const pending = await fetch(`${BASE}/managed/grants?for=pending`, { headers })
  .then(r => r.json());

// Assign a teammate to help manage the account
await fetch(`${BASE}/managed/grants/acmecorp.com/engineer@unmanned.team`, {
  method: 'POST', headers,
});

// Remove them from the account
await fetch(`${BASE}/managed/grants/acmecorp.com/engineer@unmanned.team`, {
  method: 'DELETE', headers,
});
