For developers

The actual API.

Everything from the previous page, minus the doors and the dramatic lighting. Four resource groups, a handful of endpoints, and none of them require you to believe in metaphors.

Base URL https://api.vex.unmanned.team
Authentication Threat Monitors Signals Alerts Errors

Authentication

Every request carries a bearer token, scoped to one workspace. Generate one from Settings → API Keys, or ask whoever set this up before you did.

auth-header.sh Shell 
curl https://api.vex.unmanned.team/monitor \
  -H "Authorization: Bearer $VEX_TOKEN"

Tokens don't expire on their own. Rotate them anyway. We're not your conscience, but we play one occasionally.

Threat

The "nothing personal" part, quantified. A running count of the automated noise currently aimed at your business, whether or not any of it went anywhere.

GET /threat 200 OK

A live summary of attempts against your business over a given window: how many, what kind, and where they were aimed. Nobody researched you specifically; this is the receipts.

ParameterInTypeDescription
windowquery1h, 24h, 7dOptionalHow far back to look. Defaults to 24h.
responseJSON
{
  "window": "24h",
  "attempts": 1842,
  "blocked": 1842,
  "top_vector": "credential_stuffing",
  "top_target": "email",
  "last_attempt_at": "2026-08-31T03:14:00Z"
}

"Blocked" means it never got past the front door. It does not mean nobody tried the handle.

Monitors

Connect, check, and disconnect the things watching your business. Slugs match the site: google, microsoft, aws, cloudflare, level, shopify, quickbooks, hubspot, constant-contact, slack, squarespace, and the many more we didn't have room to list here either.

GET /monitor 200 OK

Lists every monitor currently connected to your account. This is the "yes, it's still working" button.

responseJSON
[
  {
    "name": "google",
    "status": "active",
    "connected_at": "2026-06-02T14:11:00Z",
    "last_signal_at": "2026-08-27T22:04:12Z"
  },
  {
    "name": "slack",
    "status": "active",
    "connected_at": "2026-06-02T14:12:40Z",
    "last_signal_at": null
  }
]
POST /monitor/{name} 201 Created

Connects a new monitor. It wants credentials, not your firstborn.

ParameterInTypeDescription
namepathstringRequiredMonitor slug, e.g. google or microsoft.

Body shape depends on the provider. The two most common patterns:

connect-monitor.js JavaScript 
// Google Workspace: service account JSON key
await fetch(`${BASE}/monitor/google`, {
  method: 'POST',
  headers, // Authorization: Bearer <token>
  body: JSON.stringify({
    type: 'service_account',
    project_id: 'your-project-id',
    private_key_id: '...',
    private_key: '-----BEGIN RSA PRIVATE KEY-----\n...',
    client_email: 'vex@your-project.iam.gserviceaccount.com',
  }),
}).then(r => r.json());

// Microsoft 365: app registration credentials
await fetch(`${BASE}/monitor/microsoft`, {
  method: 'POST',
  headers,
  body: JSON.stringify({
    tenant_id:     'your-tenant-id',
    client_id:     'your-app-client-id',
    client_secret: 'your-app-secret',
  }),
}).then(r => r.json());
responseJSON
{
  "name": "google",
  "status": "active",
  "connected_at": "2026-08-28T09:00:00Z"
}
GET /monitor/{name} 200 OK

Status of a single monitor: when it connected, when it last checked in, and whether it's actively watching or having a moment.

responseJSON
{
  "name": "google",
  "status": "active",
  "connected_at": "2026-06-02T14:11:00Z",
  "last_signal_at": "2026-08-27T22:04:12Z",
  "last_checked_at": "2026-08-28T08:59:47Z"
}
DELETE /monitor/{name} 204 No Content

Disconnects a monitor. Vex stops watching that surface immediately. We'll miss it more than you will.

Signals

Everything a monitor noticed, and whether Vex thinks it's part of something bigger. This is the part that actually finds the way in.

GET /signal 200 OK

Every signal Vex has collected, newest first. Query params exist so you don't have to scroll forever.

ParameterInTypeDescription
sincequerystring, ISO 8601OptionalOnly return signals detected after this timestamp.
monitorquerystringOptionalFilter to one monitor's signals.
severityqueryinfo, warn, criticalOptionalFilter by how worried you should be.
responseJSON
[

    "id": "sig_8f2a1c",
    "monitor": "google",
    "type": "login.new_location",
    "severity": "warn",
    "detected_at": "2026-08-27T22:04:12Z",
    "summary": "Login for jsmith@acmecorp.com from a new country"
  },
  {
    "id": "sig_9b0e77",
    "monitor": "microsoft",
    "type": "mfa.disabled",
    "severity": "critical",
    "detected_at": "2026-08-27T22:06:03Z",
    "summary": "MFA disabled for an admin account"

GET /signal/{id} 200 OK

The full detail on one signal, including whatever else it got chained to.

responseJSON

Alerts

Configure where Vex sends signals worth interrupting you for. Slack and Teams today; smoke signals are not on the roadmap, despite the name.

GET /webhook 200 OK

Lists every place Vex is currently configured to deliver bad news.

responseJSON
[
  {
    "id": "wh_1a2b3c",
    "channel": "slack",
    "target": "#security-alerts",
    "created_at": "2026-06-02T14:20:00Z"
  }
]
POST /webhook 201 Created

Registers a new delivery channel.

ParameterInTypeDescription
channelbodyslack, teams, emailRequiredWhere Vex should send bad news.
targetbodystringRequiredChannel name, webhook URL, or email address, depending on channel.
request bodyJSON
{
  "channel": "slack",
  "target": "#security-alerts"
}
responseJSON
{
  "id": "wh_4d5e6f",
  "channel": "slack",
  "target": "#security-alerts",
  "created_at": "2026-08-28T09:05:00Z"
}

Errors

Standard HTTP status codes, used the way they were intended. No custom error taxonomy to memorize.

400You sent something malformed. Read the error message; we tried to be nice about it.
401Missing or invalid token. See Authentication, above.
404That monitor or signal doesn't exist, or never did.
429Slow down. Or don't, and see what happens.
